# CLAUDE.md

## Project Overview

`eonje` (언제충전) is a Python 3.11 project managed by **uv**.
It collects EV charger status from the Korean public API (한국환경공단 EvCharger), stores raw responses,
derives occupancy history, and serves aggregated patterns through a FastAPI service.
Design: `docs/design.md`. Requirements: `docs/requirements.md`. Read both before changing structure.

## Architecture

```
eonje/        # Pure Python package. Never imports airflow.
  cli.py      # Task entrypoint: python -m eonje.cli <job> --run-id <id>
  config.py   # Settings (pydantic-settings). The only place env vars are read.
  client/     # API client: request building, pagination, retry, response validation
  budget/     # Daily call budget: usage lookup, run/skip decision, page cap
  storage/    # raw.py (Parquet paths, read/write), models.py (SQLAlchemy ORM), db.py (engine, bulk upsert)
  transform/  # Pure functions. DataFrame in -> DataFrame out. No I/O.
  codes/      # Versioned code tables (YAML) + loader
api/          # FastAPI. Read-only over aggregate tables. Uses eonje.storage.models.
dags/         # Thin Airflow DAGs. @task.docker calling eonje.cli only.
infra/        # compose.yaml, postgres/init.sql, nginx/, migrations/ (Alembic), .env.example
tests/        # unit/ (no Airflow, no network), fixtures/ (real API responses, keys removed)
docs/         # design.md, requirements.md
```

## Boundary Rules

- **Airflow is known only in `dags/`.** `eonje/` and `api/` never import `airflow`. DAG files import only `airflow` and stdlib; they read env vars directly (they cannot import `eonje`).
- **External I/O lives only in `client/` and `storage/`.** `transform/` is pure: no HTTP, no DB, no filesystem.
- **API vocabulary (`statId`, `chgerId`, `stat`, ...) is translated once in `transform/observations.py`** into internal names (`stat_id`, `charger_id`, `status_code`). Everything downstream uses internal names only.
- **`storage/models.py` is the single source of the DB schema.** Alembic migrations are autogenerated from it; `api/` queries the same models.
- **Bulk loads never use `session.add` per row.** Use `insert(Model).values(rows).on_conflict_do_update(...)`.
- **Raw responses are stored as received** — all columns as strings, unknown fields kept. Type conversion happens in `transform/`.
- Settings are read in `config.py` only. Collection interval, daily limit, page size, served regions are all settings, never literals.

## Data Rules

- Every task is **idempotent per `run_id`**: rerunning the same run produces the same tables. Raw: overwrite the `run=<ts>` directory. `obs_status`: ignore on conflict. Transitions/sessions: upsert. Aggregates: delete the window, recompute.
- `statUpdDt` is **not** a transition time (operator-dependent heartbeat). Transitions are derived by comparing against `charger_state`.
- Unknown status codes are stored, never rejected. Do not hardcode status enums; map at aggregation time via `codes/`.
- Missing observation windows are "unknown", not "available". They never enter an occupancy denominator.
- The daily API limit (`API_DAILY_LIMIT`) must never be exceeded. Every call is logged to `api_call_log`; `budget/` decides before any fetch.

## Error Handling Convention

- `client/`: retry transient HTTP errors with backoff (tenacity); raise after exhaustion. Never swallow a failed page silently — log it to `api_call_log` with the result code.
- `transform/`: raise on contract violations (missing required column); never catch broadly.
- `storage/`: raise on write failure. Writes are transactional per task.
- Unknown fields/codes in API responses are **not** errors: keep and report.

## Common Commands

```
uv sync --all-extras          # install
uv run pytest                 # tests (no network, no DB)
uv run ruff check . && uv run ruff format --check .
uv run mypy
docker build -t eonje:dev .   # task + API image
docker compose -f infra/compose.yaml up -d
```

## Git & PR Conventions

- Managed via custom commands: `/commit`, `/create-pr`, `/review`
- Branch from `main`; never commit to `main` directly
- Squash merge PRs (`gh pr merge --squash`); PR title follows Conventional Commits
- Never commit `.env`, service keys, or fixtures containing a key
